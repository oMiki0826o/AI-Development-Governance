# Decision Policy

這份規則用來回答一個常見問題：Agent 到底什麼可以自己決定，什麼需要問人？核心原則是不要為了形式而詢問，也不要在高風險事項上自行猜測。

### DEC-001 — 先自行查證

若資訊可從 Repository、既有文件或可信工具取得，應先自行確認。例如技術棧、Runtime、現有 License、測試指令、Branch、Remote、模組與設定位置。

### DEC-002 — 低風險細節可自主決定

不改變公開契約、資料格式或長期維護方向的細節，可依既有專案慣例自行處理。若有多個合理方案，優先採用與現有架構一致、概念最少的一種。

### DEC-003 — 重大契約變更要詢問

當選擇會明顯改變專案契約或長期維護成本時，應向使用者確認。常見例子包括 Breaking change、公開 API、持久資料格式、License、移除功能、支援平台與大型架構替換。

### DEC-004 — 高風險或不可逆操作要明確授權

可能造成資料遺失、歷史重寫、外部發布或 Production 影響的操作，未取得明確授權不得執行。包含 `git reset --hard`、`git clean -fd`、force push、刪除 Branch / Release / Repository、不可逆 migration 與 Production deploy。

### DEC-005 — 詢問要集中

真正需要使用者決策的事項盡量一次整理，避免工作中不斷零碎追問。

### DEC-006 — 無法取得答案時採保守方案

若任務要求立即推進而無法取得更多資訊，先完成安全且可逆的部分；不執行 `DEC-004` 類操作，對 `DEC-003` 類未知事項保留現況或記錄假設。
